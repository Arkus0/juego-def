# implement-workpack

Implement exactly one authorized workpack.

## Flow

1. Reconstruct current `main`, the canonical branch/PR if one exists, and the exact WP.
2. Read only the direct design/product/research authorities the WP actually binds.
3. Record a short dependency check: accepted prerequisites, guarantees consumed, new guarantees owned here, and reopen conditions.
4. Implement only Allowed scope; respect Forbidden scope and cost/dependency rules.
5. Use Unity/MCP/Blender/GC2/scripts as needed. If an operator performs bounded physical work, Worker remains owner of interpretation and final candidate.
6. Produce the evidence required by the WP. For visual/runtime claims, inspect the product-relevant view and Play Mode/runtime when applicable.
7. Finish all repository/evidence bytes, stop overlapping writers and read exact HEAD as `PRODUCT_SHA`.
8. Perform strict Worker pre-review against Acceptance/DoD and plausible failure modes. Repair any in-scope blocker before freeze.
9. Record readiness bound to `PRODUCT_SHA`, freeze the candidate and stop for a fresh Reviewer.

## Factory WPs

A factory claim requires more than one attractive result. Check reusable input discovery, transformation/assembly path, validation, lineage/provenance, batch/repeatability evidence and whether the next normal asset is production rather than new R&D.

## Stop condition

Report exact `PRODUCT_SHA` and STOP for independent review. Do not merge or issue independent PASS unless explicitly operating in a later authorized post-PASS role.
