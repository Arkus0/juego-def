# WP-M0-00 — Gameplay Integration Fixture

Status: **READY / PARALLEL**  
Class: PRODUCT INTEGRATION FIXTURE  
Depends on: Bootstrap Unity + GC2 Core PASS  
Blocks: `WP-CITY-URBAN-01` only; does **not** block graphical factory R&D

## Claim

juego-def has a tiny retained GC2 gameplay fixture at the real player/camera scale: the player can walk a short route, use/examine one world interaction and interact with one NPC in Play Mode.

M0 exists to validate **integration conditions that the asset factories themselves should not own**: player scale, camera read, collision/reach, interaction distance, NPC encounter framing and basic GC2 wiring.

It is not a milestone that justifies delaying asset-pipeline research. `WP-PROD-ASSET-00` may run immediately from the accepted bootstrap.

## Binding inputs

- `Docs/design/GAME_VISION.md`
- `Docs/design/VISUAL_BIBLE.md`
- `Docs/architecture/GC2_FIRST_ARCHITECTURE.md`
- `Docs/architecture/PRODUCTION_AUTHORING_DECISION.md`
- accepted bootstrap scene/evidence under `Docs/evidence/BOOTSTRAP-UNITY-GC2/`

## Required retained output

Create a tiny retained fixture containing at minimum:

1. accepted GC2 player + third-person camera;
2. short walkable route at believable pedestrian scale;
3. one real world/hotspot interaction;
4. one examinable/use result;
5. one non-capsule NPC;
6. one real GC2 interaction with that NPC;
7. enough lighting/readability to judge camera, reach and scale.

The fixture may later be replaced by keeper content. It is not itself an environment-factory deliverable.

## Art scope

- real admitted assets are preferred where already available;
- explicit `PROXY` structural aids are allowed;
- proxy geometry may never be claimed as keeper art;
- do **not** spend M0 time deriving broad architectural kits, wardrobe systems or animation pipelines — those belong to factory WPs.

## Operator loop

`inspect -> bounded build/wire -> Play Mode -> inspect runtime/capture -> correct real integration issue -> replay`

At least one evidence-driven correction is desirable where a real issue occurs.

## Evidence

Retain under `Docs/evidence/WP-M0-00/`:

- fixture scene path;
- movement/interaction/NPC proof;
- at least 2 useful captures;
- console status;
- owner keyboard/mouse feel note;
- explicit proxy list;
- any collision/reach/camera/GC2 correction worth carrying forward.

## PASS

PASS when:

- the retained fixture compiles/plays;
- owner can walk it with the accepted GC2 player/camera;
- one world interaction works;
- one NPC interaction works;
- camera/interaction reach/scale are usable enough to validate later assets;
- no blocking runtime issue remains;
- no H0/H1 or graphical factory was smuggled into M0.

## FAIL

FAIL if interaction is staged/faked, success needs uncaptured hand repair, GC2 baseline regresses, or M0 expands into an environment/character/animation production lane.

## Handoff

M0 can be completed at any point while `PROD-ASSET-00` and early factories progress. It must be PASS before `WP-CITY-URBAN-01` integrates the first keeper block.
