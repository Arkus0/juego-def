# WP-M0-00 — First Walking Street

Status: **READY / NEXT**  
Class: PRODUCT SLICE / FOUNDATION-TO-GAME TRANSITION  
Depends on: Bootstrap Unity + GC2 Core PASS  
Blocks: production lanes in this directory

## Claim

juego-def has its first retained, playable GC2 street: the player can walk through a short port-town route, understand the space, examine/use a world interaction and interact with one NPC in Play Mode.

M0 proves the direct production path `Unity + GC2 + bounded MCP operator` on a visible game fragment. It does **not** prove final art breadth or living-world depth.

## Required keeper output

Create a **new retained M0 scene or retained evolution of the bootstrap**, clearly named and separate from throwaway tests, containing at minimum:

1. existing GC2 player + third-person camera, tuned to comfortable walking inspection;
2. one short, legible port-town street/route at believable pedestrian scale;
3. one door/hotspot or equivalent world interaction;
4. one examinable object with a visible/textual result;
5. one NPC in the same route;
6. one real GC2 interaction with that NPC producing a brief visible response and, if practical, a simple gesture/animation;
7. lighting/atmosphere coherent enough with the Visual Bible that the scene is not a misleading cube test.

## Environment scope

M0 is **not** `PROD-ENV-01`. It does not require the final environment factory or a complete Quaternius-derived town kit.

However:

- primitive geometry may be used as an explicitly temporary structural aid;
- primitive boxes may **not** be presented as keeper facades/buildings by merely attaching decorative assets;
- use real admitted assets/components wherever reasonably available;
- composition must already care about human scale, street width, ground contact, entrances, sightline and a recognisable port-town cue;
- if the available corpus cannot support a credible keeper element, mark it `PROXY` rather than silently treating it as approved art.

## Operator execution loop

Use the adopted bounded operator for Unity work.

Required loop:

`inspect current project/assets -> plan bounded change -> build/wire -> Play Mode -> inspect console/runtime/capture -> correct at least one observed issue -> replay`

The correction must respond to real evidence: collision, scale, camera, interaction reach, lighting, hierarchy, broken GC2 binding, navigation/readability, etc. Do not invent a ceremonial correction if the first result is flawless; in that case record the checks performed and any small tuning actually made.

## Gameplay requirements

### Player/camera

- preserve working GC2 player/camera baseline;
- tune normal movement toward a walking/exploration feel rather than default jog if needed;
- owner performs one keyboard/mouse feel check before PASS.

### World interaction

At least one GC2-triggered/hotspot-style interaction must have an observable result. Examples: door responds, sign/object produces inspection text, object changes visible state.

### NPC

The NPC may use a placeholder/non-final civilian model in M0, but must not be a capsule/cube.

Interaction must be actual gameplay wiring, not a screenshot-only staging. It may be one line/local UI; Dialogue module is not required.

## Evidence

Retain under `Docs/evidence/WP-M0-00/`:

- short execution/result README;
- scene path and exact key package versions if changed from bootstrap;
- at least 3 useful captures: route/readability, interaction, NPC encounter;
- Play Mode proof of player movement and both interactions;

- one owner hand-test note;
- operator failure/correction notes where materially useful;
- list of known `PROXY` elements that must not be mistaken for production-approved art.

An automated route walk/collision probe is encouraged if cheap, but becomes mandatory only in `PROD-ENV-01`.

## PASS

PASS only when all are true:

- project opens/compiles and retained M0 scene enters Play Mode;
- owner can walk the intended route with GC2 player/camera;
- route is legible and scaled plausibly in third person;
- one world interaction works;
- one NPC interaction works;
- no blocking console/runtime issue remains;
- scene has at least one coherent port-town/Atlantic identity cue beyond pure primitives;
- proxies are explicitly identified;
- evidence exists;
- no H0/H1 or unnecessary custom framework was introduced.

## FAIL / stop conditions

FAIL this WP if:

- success depends on hand repair that is not captured/repeatable;
- GC2 player/camera baseline regresses materially;
- interaction is faked rather than wired;
- scene is claimed as keeper-quality while architecture is effectively greybox + pasted decoration;
- work expands into dialogue system selection, schedules, inventory, quests, combat, full environment factory, or broad NPC population;
- a new large framework is built because the operator could not perform one local task without first proving that framework is necessary.

## Non-goals

No Dialogue/Inventory/Quests/Behavior/Melee/Perception requirement. No final district. No final NPC art. No full interior. No final performance target. No H1 lifecycle witness.
