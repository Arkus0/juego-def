## Claim

The accepted Potes reference contract can be translated into keeper-quality Unity environment work without returning to procedural urban/facade design.

Reconstruct the exact **8–15 real buildings** named by `WP-POTES-00/sector-01/FIRST_SLICE.md`, together with the directly required street/public-space/terrain context, using real Potes as exterior authority and ENV01 only as reusable production vocabulary.

This is the physical falsification gate for the whole casco.

## Binding inputs

Consume only the frozen `WP-POTES-00` authority for factual placement:

- exact `POT-Bxxx` First Slice membership;
- metric geometry and coordinate transform;
- street/public-space ledger;
- per-building facade/opening/roof observations;
- fixed comparison viewpoints;
- source/confidence states;
- ENV01 reuse map and missing-asset list.

If a factual exterior requirement is missing or marked blocking `UNKNOWN`, do not invent it silently. Resolve it through the source path allowed by POTES-00 or return a bounded blocker.

## Physical scope

Build:

- all First Slice buildings;
- their exact visible footprint/massing relationships;
- required street/lane/plaza geometry;
- required terrain/elevation;
- required river/bridge/retaining elements when the slice includes them;
- structural walls/steps/railings/vegetation needed by the pinned reference views;
- fixed identity-bearing facade/public-space elements supported by the pack.

Do not build unrelated surrounding casco.

## ENV01 posture

Reuse in this order:

`REUSE_EXACT -> RECOMPOSE -> ADAPT -> CREATE_MISSING`

A real Potes dimension or facade fact always beats an ENV module dimension.

Do not keep an ENV01 generated building merely because it already exists.

## Fidelity gate

Where source precision supports it:

- footprint/public-edge positional error <= **0.5 m**;
- real adjacency/party-wall relationships preserved;
- real storey rhythm/massing preserved;
- documented door/window counts and approximate positions preserved;
- documented roof topology/orientation preserved;
- documented major balconies/galleries/arcades preserved;
- no procedural/random opening layout on referenced facades.

Transient clutter is not forensic. It may use bounded ENV dressing after the structural reference is correct.

## Gameplay-scale proof

The First Slice must be experienced from the actual third-person product camera/player.

Prove:

- continuous walkability through every included public route;
- no blocking threshold/street collisions caused by reconstruction;
- no obvious scale mismatch from gameplay camera;
- elevation/steps/bridge relationships are traversable where intended;
- comparison captures from every fixed POTES-00 viewpoint;
- at least one traversal capture showing the slice as continuous game space.

No interiors are required beyond exterior thresholds explicitly necessary for the slice.

## Owner visual gate

The Owner must judge whether the result reads as **the referenced Potes place**, not merely as “Potes-flavoured ENV01”.

A technically valid but generic/reinterpreted result does not pass.

## Acceptance

PASS requires:

- every First Slice `POT-Bxxx` is present exactly once;
- no extra invented building is used to repair composition;
- geometry and facade fidelity meet the POTES-00 contract where evidence exists;
- unknown facts are explicit rather than fabricated;
- public route is traversable;
- ENV01 acts as kit, not layout authority;
- Owner accepts the visual identity;
- Worker demonstrates the reconstruction path is repeatable enough to complete the sector.

## FAIL

FAIL if the result is a procedural approximation, a dressed greybox, a visually generic “mini Potes”, a set of individually plausible buildings with wrong real relationships, or if faithful production still requires manually rediscovering facts already meant to exist in Sector Pack 01.
