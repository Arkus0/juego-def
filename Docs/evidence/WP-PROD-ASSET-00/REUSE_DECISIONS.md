The source archive and exported FBX files are never edited in the vault. Intake copies are ignored by Git; only metadata, openly licensed utility code and evidence enter the public repo. The utility was first tested in a disposable project, then pinned in `juego-def` so the UAL import step is repeatable on a clean clone.

Replacement boundary: this is an Editor-only helper, not a player/runtime dependency. If replaced, remove its source/Unlicense and the thin `JDAssetIntakeApplyUAL` wrapper together, then provide another repeatable way to set UAL Humanoid/axis/root/loop import metadata on a clean clone. Existing FBX and Unity content remain ordinary assets. No upstream code changes were needed beyond line-ending/trailing-whitespace normalization when vendoring; Unity itself locally resaves the 14 Medieval Village materials on import, and intake preserves those ignored local copies.
